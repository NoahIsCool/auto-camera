# ac-vision

Detection and per-frame tracking for Auto Camera, behind traits that do not
depend on a model runtime.

| Item | What it does |
|---|---|
| `Detector` | Slow, open-vocabulary detection: `detect(&mut self, &VideoFrame, &[PromptQuery]) -> Result<Vec<Detection>, VisionError>` |
| `Tracker` | Fast per-frame tracking of known subjects: `start`, `update`, `stop`, `tracked` |
| `TemplateTracker` | Pure-Rust NCC template tracker (grayscale pyramid, constant-velocity prediction, local search, 0.95/1.0/1.05 scale search, ambiguity check) |
| `ScriptedDetector` | Detections from a closure or keyframe table, for tests and demos |
| `OnnxOwlDetector` | OWLv2 / OWL-ViT on ONNX Runtime, feature `onnx` (off by default) |
| `owl::*` | Pure OWL pre/post-processing: letterbox, CLIP normalization, sigmoid, box decoding, token packing |
| `boxes::*` | `clamp_box`, `cxcywh_to_rect`, `nms_indices`, class-aware `nms` |

All boxes are normalized source coordinates (`ac_core::Rect`), clipped to the
frame; scores and confidences are in `0..=1`.

## Template tracker

See the `tracker` module docs for the algorithm, trust rules and cost model.
In short: frames are reduced to a 384 px wide luma pyramid; each subject is
matched on the level where its box is at most 32 px, over a window of half its
size around the constant-velocity prediction. It moves only on a strong,
unambiguous peak; otherwise it coasts and reports low confidence. The
detector re-anchors subjects; the tracker never retires one by itself.

Measured with `cargo run --release -p ac-vision --example track_bench` on a
4-core 2.1 GHz Xeon VM: 16 subjects on 1080p in 7.4 ms per frame (most of it
the RGBA-to-luma downscale, which is shared by all subjects).

## OWLv2 through ONNX Runtime (`--features onnx`)

**Status: unvalidated against a real model.** The runtime plumbing is tested
on Linux CPU (ONNX Runtime 1.31) with synthetic graphs that use the names and
shapes below (`tests/fixtures/owl`, generated by `make_fixtures.py`). The
export commands, tensor names and CoreML behaviour still need to be confirmed
on a Mac with a real export.

### Building

The `ort` crate (2.0.0-rc.13) downloads ONNX Runtime 1.28 at build time. On
Apple Silicon the download includes the CoreML execution provider, which the
detector registers when `OwlConfig::use_coreml` is set (the default); nodes
CoreML cannot run fall back to the CPU. To build against a local ONNX Runtime
(1.27 or newer) instead, for example the `libonnxruntime` inside the
`onnxruntime` Python wheel:

```sh
export ORT_LIB_LOCATION=/path/to/dir/with/libonnxruntime   # .so or .dylib
export ORT_PREFER_DYNAMIC_LINK=1
export LD_LIBRARY_PATH=$ORT_LIB_LOCATION                    # DYLD_LIBRARY_PATH on macOS
cargo test -p ac-vision --features onnx
```

### Getting a model

Two layouts are accepted (`OwlModel`):

**Combined** (simplest; the text tower runs on every call):

```sh
pip install optimum-onnx   # older releases: pip install "optimum[exporters]"
optimum-cli export onnx --model google/owlv2-base-patch16-ensemble \
    --task zero-shot-object-detection models/owlv2-base-onnx/
# -> models/owlv2-base-onnx/model.onnx and models/owlv2-base-onnx/tokenizer.json
```

```rust
let detector = OnnxOwlDetector::load(
    OwlModel::Combined { model: "models/owlv2-base-onnx/model.onnx".into() },
    Path::new("models/owlv2-base-onnx/tokenizer.json"),
    OwlConfig::default(),
)?;
```

**Split** (text embeddings cached per prompt, so steady-state detection runs
only the image side):

```sh
pip install torch transformers onnx onnxruntime
python crates/ac-vision/scripts/export_owlv2_split.py \
    google/owlv2-base-patch16-ensemble models/owlv2-split-onnx/
# -> text_encoder.onnx, detector.onnx, tokenizer.json; prints a parity check
```

### Expected tensors

| Graph | Name | Type and shape |
|---|---|---|
| combined, text encoder | `input_ids` | `i64 [Q, 16]`, CLIP ids `[BOS, …, EOS]`, padded with `!` (id 0) |
| combined, text encoder | `attention_mask` | `i64 [Q, 16]` |
| combined, detector | `pixel_values` | `f32 [1, 3, S, S]`, S = 960 (base) or 1008 (large) |
| detector | `query_embeds` | `f32 [1, Q, 512]` |
| text encoder | `text_embeds` | `f32 [Q, 512]` |
| combined, detector | `logits` | `f32 [1, P, Q]`, P = (S/16)² = 3600 for base |
| combined, detector | `pred_boxes` | `f32 [1, P, 4]`, `(cx, cy, w, h)` in `0..1` of the padded square |

Names can be changed through `OwlConfig::names` if an export differs; loading
fails with the graph's actual input names when one is missing.

Preprocessing follows the OWLv2 processor: the frame is placed at the top-left
of a square and padded with grey (0.5) at the bottom/right, resized to S
(anti-aliased), and normalized with the CLIP mean and standard deviation.
Postprocessing applies a sigmoid per (patch, query), keeps scores at or above
the query's threshold (`OwlConfig::score_threshold`, default 0.1, or
`query_thresholds`), maps boxes back to the source by undoing the padding,
clips them, and runs class-aware NMS (IoU 0.3, at most 16 per query). OWL-ViT
v1 exports (`google/owlvit-base-patch32`, S = 768, P = 576) use the same
graph interface; v1 was trained on stretched rather than padded images, so
expect slightly lower scores.
